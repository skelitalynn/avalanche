## 状态与完成规则

`TODO → DOING → VERIFY → DONE`；执行受阻时用 `BLOCKED`，记录原因和恢复条件。

- `VERIFY`：实现完成，测试或验收尚未完成。
- `DONE`：对应验收项全部满足，并有实际验证证据。仅写完代码或拿到交易哈希不能标为完成。
- 实现任务开始前须有明确 Spec、实施步骤、验收项和验证方式；工具确定后写入具体命令。
- 证据格式：日期、代码版本/相关文件、命令或操作步骤、预期与实际结果；真实链上验收额外记录网络、地址、交易哈希和回执结果。
- 模拟测试与真实测试网结果分别记录。失败结果保留，不用修改预期来消除失败。
- 认领任务时补齐负责人、分支与 PR 状态；一项任务一位负责人，需要多人实现时拆子任务。已有未认领任务不预填成员身份。
- DONE 表示任务验收通过，是否进入 main 以 PR 合并状态为准；未合并的能力不能计为主线已交付。
