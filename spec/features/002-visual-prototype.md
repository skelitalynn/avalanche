# 002 SituationSHIT 单文件交互原型

状态：READY，仅针对 mock 原型；001 的 Q1–Q7 仍待确认。
关联任务：T010。负责人：本次对话用户，AI 助手实施。

## 需求来源与范围

2026-09-19 用户要求按照最新需求文档改出新的 HTML，随后明确改为连续流程，并要求关系建立后可增减约定、申诉对方违约。原型为中文移动端优先的单文件，不替代 React 正式工程，不连接钱包、RPC 或真实资金。

## 功能行为

- 首页进入连续流程；依次创建约定、填写两类金额与三位监督人、双方签署、双方模拟入金，再进入关系主页。
- 主页展示当前约定版本与分人分类型资金，支持提出修订、发起申诉、正式确认及双方正常结束。
- 争议页包含确认时间、截止时间、回应和申诉状态，并提供说明、回应、接受结束和提出争议入口。未定路径只提示，不产生结算。
- 监督页只展示必要争议信息，每名好友一票，两票违约后模拟结算；不足两票不转移保证金。
- 正常结束各退本人恢复基金和保证金；B 违约时 A 收到双方保证金，B 只收本人基金。结束后不能再次入金或结算。
- A/B 角色可在签署后切换；不代表身份认证或真实计时。状态只存在内存，刷新重置，不提供虚假的跨设备邀请链接。
- Q1–Q7 不作业务定案；同额、整笔入金、输入范围、持续时间及完成情况是评审示例。无真实截图，使用 HTML/CSS 插画与 mock 数据。链详情默认折叠。

## 2026-09-19 连续流程与约定变更

来源：用户要求从“开始一段关系”逐步完成创建、签署，建立后可增减约定并申诉对方违约。此次仅扩展单文件 mock；001 正式链上功能仍为 DRAFT。

- 移除七页自由导航和预装争议场景。按填写约定 → 资金与好友 → 双方签署 → 双方入金 → 关系主页推进；返回编辑保留输入，已签署后不可退回修改协议。越级 hash 导航回到当前合法步骤。
- 同页使用明确的 A/B 模拟身份切换，每次只能签署、存款、回应或确认属于当前角色的操作；不把模拟身份当成安全认证。
- 初始三条约定可编辑、删除；可添加自定义文字约定，至少保留一条。用户文本按文本安全展示。
- 建立后的增减约定生成修订提案，由发起方确认，再由另一方接受后替换生效并递增版本；拒绝或撤回保留原版。此为本次原型假设，需产品方确认后才能用于真实业务。资金与监督人不能通过约定修订修改。
- 正式确认、申诉或结束请求期间锁定约定编辑。待确认修订期间不能发起新申诉或结束，避免使用未定版本。争议保留发起时的版本与约定快照。
- 申诉可选择当前生效约定、说明情况，自动指定另一人为被申诉方。失联申诉仍需先正式确认并模拟超期且无回应；删除失联约定后不再显示该入口。一般约定可发起 mock 申诉并由对方回应，但裁决标准与资金后果待定，不自动触发投票转账。
- 失联演示可进入三名好友一人一票的监督阶段；两票后按实际被申诉方结算，A/B 对称。正常结束需要双方确认。
- 所有修改仅内存保存，刷新重置；页面提供统一 mock 提示。退出编辑放弃草稿，不改变已生效约定。
